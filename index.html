02 / SKILL ROADMAP

What to Learn & In What Order

Two parallel tracks — Salesforce and AI — that converge in your projects. Learn enough AI to build with it, not enough to explain gradient descent at a whiteboard. Applied AI, not theoretical ML.

☁️ Apex (Deep Mastery)
MONTH 1–2
  • Governor Limits: Build instincts for DML, SOQL, heap. Know every limit cold.
  • Collections & SOQL: Bulkification, aggregate queries, relationship queries.
  • Triggers: One trigger per object, handler class pattern — never business logic in trigger body.
  • Async Apex: Batch (data volumes), Queueable (chaining — CRITICAL for AI calls), Scheduled, Future (legacy).
  • HTTP Callouts: You already understand this from API testing. Now apply it — HttpRequest, HttpResponse, JSON parsing, mock callouts.
  • Test Classes: 90%+ habit. @testSetup, meaningful assertions. Mock callouts with HttpCalloutMock.
  • AI Relevance: Every AI integration goes through Apex callouts. Queueable is essential because LLM API calls are too slow for synchronous Apex limits.
⚡ LWC (Component Development)
MONTH 2–3
  • Lifecycle Hooks: connectedCallback, renderedCallback — know when each fires.
  • Wire + Imperative: Wire for reactive data; imperative for AI API calls (loading states matter).
  • Custom Events: Component communication patterns.
  • Async/Await in JS: Critical — AI callouts are async. Handle promises correctly in LWC.
  • SLDS: Build clean UIs without fighting the design system.
  • AI Relevance: Your LWC is the chat UI, the AI response display, the "Generate Summary" button. It's the face of every AI feature you build. Loading spinners, streaming text display, error states — all LWC.
🔗 Integrations
MONTH 3
  • Named Credentials: ALWAYS use for LLM API endpoints. Never hardcode OpenAI keys.
  • REST Callouts: HttpRequest/HttpResponse — you will use this for every LLM API call.
  • Platform Events: Key for async AI processing — trigger the AI job, respond via event.
  • External Services: OpenAPI schema import — can import OpenAI spec.
  • AI integration pattern: User triggers LWC → Apex Queueable → Named Credential → OpenAI/Anthropic API → Platform Event → LWC re-renders with result. Know this pattern cold.
🏛️ Architecture
MONTH 4–5
  • Enterprise Patterns: Selector, Domain, Service, Application (Andy Fawcett book — non-negotiable).
  • Sharing Model: OWD, role hierarchy, Apex managed sharing.
  • Data Architecture: Record volumes, indexes, data skew — becomes very relevant when designing AI training datasets.
  • Salesforce Well-Architected: Trusted, Easy, Adaptable pillars.
  • AI architecture: How to design systems that send data to LLMs, handle latency, manage cost, and fail gracefully. This is new and almost no one has written the playbook yet — you will.
🤖 AI / LLM Stack — Applied (Not Theoretical)
MONTH 1 → ONGOING
LLM Foundations (Month 1)
  • How LLMs work conceptually: Tokens, context window, temperature. You don't need transformers math — you need to know why "context window" matters when building features.
  • Prompt engineering: System prompts, few-shot examples, chain-of-thought. This is your superpower. Practice: write prompts for case summarization, lead scoring, email drafting.
  • OpenAI API basics: Chat completions endpoint, models (GPT-4o, GPT-4o-mini), pricing, rate limits. Call it from Apex.
  • Anthropic Claude API: Alternative to OpenAI. Good to know both — enterprise clients use both.
RAG + Vector DBs (Month 2–3)
  • RAG (Retrieval-Augmented Generation): Instead of asking the LLM to remember facts, you retrieve relevant docs and inject them into the prompt context. This is how you build AI that knows about your Salesforce data.
  • Vector databases: Pinecone (simplest to start), Weaviate, or pgvector. Store embeddings. Search by semantic similarity. Understand: embedding → vector store → similarity search → context injection.
  • Embeddings: text-embedding-ada-002 (OpenAI) or similar. Convert text to numerical vectors. Use for semantic search over SF data.
  • Practical exercise: Build a simple RAG demo outside Salesforce first (Python + Pinecone + OpenAI). Then port the pattern into Apex.
Salesforce AI Ecosystem (Month 3–4)

03 / SALESFORCE + AI INTEGRATION STRATEGY

How to Bring AI Into Salesforce

There are four distinct ways to integrate AI into Salesforce. You need to understand all of them, build with at least three, and be able to choose between them in a system design conversation.

Pattern 1 · Apex Callouts to LLM APIs
The most powerful and flexible pattern. Your Apex code calls an external LLM API (OpenAI, Anthropic, Google Gemini) via an HTTP callout. You control everything — the prompt, the parsing, the error handling. This is what makes you a developer rather than a user of AI tools.

WHY QUEUEABLE
Never call LLMs synchronously
LLM API calls take 1–8 seconds. Apex synchronous limit is 5s for callouts. Use Queueable for longer operations. Use Platform Events to return results asynchronously to the LWC.
PROMPT DESIGN
System prompt + data injection
Build your prompt in Apex: system role defines the AI's job, user message contains the Salesforce data (SOQL results, JSON-serialized records). Never hardcode prompts — store in Custom Metadata for versioning.
ERROR HANDLING
LLMs fail. Design for it.
Rate limits (429), timeouts, hallucinated JSON formats, empty responses. Always wrap in try-catch. Log to a custom AI_Log__c object. Have a graceful fallback — show the user something useful even if AI fails.
Pattern 2 · AI-Powered Flows & Automation
Use Salesforce Flow as the orchestrator. Call Apex AI actions from Flow. This makes AI accessible to admins (declarative + Apex action hybrid). Extremely valuable for enterprise clients who want admin-configurable AI features.
FLOW + APEX ACTION
Invocable Apex for AI
Build an @InvocableMethod that calls an LLM. Flow calls this action as a step. Result is stored in a flow variable and written back to a Salesforce field. Admins configure the trigger and logic; your Apex does the AI.
PROMPT BUILDER
Salesforce-native prompt management
Prompt Builder (GA in Winter '25) lets you create prompt templates with Salesforce merge fields and grounding data. Use it to create reusable prompts that admins can modify. Works with Einstein models and custom LLM connections.
USE CASES
Auto-classify, auto-route, auto-draft
Auto-classify incoming cases on creation. Auto-generate response drafts when cases open. Auto-score leads on creation. Auto-summarize opportunity history before a meeting. All triggered by Flow, powered by your Apex AI action.
Pattern 3 · Agentforce (Custom AI Agents)
Agentforce is Salesforce's most important AI initiative in 2025. It lets you build autonomous AI agents that can take actions inside Salesforce on behalf of users. A custom Agentforce agent understands natural language requests, decides which actions to take, and executes them. This is where the market is heading — and where almost no developer has depth today.
CORE CONCEPTS
Topics, Actions, Agents
Agent: The AI persona with instructions and a scope. Topics: Areas the agent can handle (e.g. "Case Management"). Actions: Specific tasks the agent can perform — either Apex @InvocableMethod, Flow, or pre-built actions. The LLM decides which action to invoke.
CUSTOM ACTIONS
Your Apex as agent capabilities
Build @InvocableMethod Apex classes. Mark them as agent actions. The agent LLM can now call your code autonomously. Example: "Summarize the top 5 open cases for this account" → agent calls your SOQL + LLM summarization Apex.
BUILD ORDER
Start simple, grow complex
Month 3: Build one custom Agentforce action. Month 4: Build a full custom agent with 3–4 actions. Month 5: Demo to interviewers. This specific demo — "here's a Salesforce agent I built" — is the single most impressive thing you can show right now.
Pattern 4 · Einstein Platform + Data Cloud (Know It, Don't Over-invest)
The native Salesforce AI platform. Important to understand conceptually and able to discuss architecturally. You don't need to be a Data Cloud specialist — you need to know when to use it vs building custom AI, and be able to have an intelligent conversation with a client about it.
  • Einstein Prediction Builder: No-code ML on SF data. Know when to use it instead of calling OpenAI.
  • Einstein for Service: Case classification, recommended articles, case summarization. Native features — know they exist so you don't rebuild what's already there.
  • Einstein Copilot Studio: Where you build custom Agentforce agents. Use this.
  • Prompt Builder: Manage prompt templates across the org. Use this from Month 3.
  • Data Cloud basics: Understand data streams, data model objects (DMO), unified profiles. Know it powers AI personalisation.
  • Model Builder: Bring your own LLM (BYOLLM). Connect custom LLMs to Salesforce. Available now. Use this to connect your OpenAI Named Credential properly.
  • When to use native vs custom: Native Einstein for standard CRM AI tasks. Custom Apex callouts when you need specific behavior, custom prompts, or external model control.
  • GDPR note: Data Cloud processes data within Salesforce's EU data centers if configured correctly. Critical point for European clients.

07 / INTERVIEW PREPARATION

Technical Interview Playbook: SF + AI

European interviews now include an AI tier — from basic AI awareness questions in HR screens to system design scenarios for architect roles. You need answers for all levels. Here are the questions you will actually be asked.

Apex Deep Questions
ROUND 2
  • "How do you bulkify a trigger?" — Collections, Maps by Id, no SOQL/DML in loops.
  • "Batch vs Queueable vs Future — when to use each?" — Batch: 50M+ records. Queueable: chaining, complex types, AI callouts. Future: legacy, simple async.
  • "How do you call an external API from Apex?" — HttpRequest, Named Credentials, async pattern. If they say "like an LLM API" — demonstrate with your case summarization project.
  • "Why can't you call OpenAI synchronously from Apex?" — Callout timeout, governor limits. Queueable + Platform Event pattern.
  • "How do you test an Apex class that calls OpenAI?" — HttpCalloutMock interface, Test.setMock(), mock the JSON response, assert the parsing logic.
LWC + Integration Questions
ROUND 2
  • "How would you display streaming AI responses in LWC?" — Platform Events for real-time updates; polling pattern as fallback; wire to Platform Event channel.
  • "Wire vs imperative Apex — when to use which?" — Wire for cacheable reactive data; imperative for AI calls (need loading state, error handling, non-cacheable).
  • "How do siblings communicate?" — Through parent via custom events, or Lightning Message Service for unrelated components.
  • "How would you show an AI loading state in LWC?" — isLoading reactive property, conditional template rendering, spinner component, disable button while processing.
  • "REST vs SOAP, Platform Events vs CDC?" — REST: modern, JSON. PE: custom business events you define. CDC: system-generated record change events for sync.
AI Practical Questions
ROUND 2–3
  • "What is RAG and how would you implement it in Salesforce?" — Explain: retrieve relevant data (SOQL or vector search) → inject as context → LLM generates grounded answer. Reference your chatbot project.
  • "What is Agentforce?" — AI agent platform on Salesforce. Topics define scope, Actions are Apex invocable methods, the LLM orchestrates which action to call. You've built one.
  • "How do you handle LLM hallucinations in a production feature?" — Grounding (inject real SF data), structured output (JSON schema), validation of response before displaying, confidence thresholds, human-in-the-loop for critical decisions.
  • "How do you ensure GDPR compliance when sending Salesforce data to an LLM?" — Anonymize/pseudonymize PII before sending, use Azure OpenAI (EU data residency), data processing agreements, consent management, audit logging. This answer alone will impress EU interviewers.

Architecture Scenarios (AI + SF)

⚠️ Common Mistakes — Especially for SF + AI

#01
Treating AI as a separate topic rather than a Salesforce skill AI without Salesforce context is just ChatGPT usage. Salesforce without AI is a standard developer. The value is in combining them. Every AI thing you learn should immediately be applied inside Salesforce. If you've just learned about RAG, your next commit should be an Apex class that does context injection.
#02
Ignoring GDPR when designing AI features In European interviews, if you propose sending raw Salesforce customer data to OpenAI without mentioning GDPR, data processing agreements, or anonymization — you will fail the architecture round. This is not optional knowledge in the EU. Study the basics: pseudonymization, data residency, legitimate interest, DPAs.
#03
Calling LLMs synchronously from Apex The most common technical mistake when starting. Synchronous Apex callouts for LLMs will time out and hit governor limits. Always use Queueable (or Future as legacy). Always use Platform Events to return async results to the UI. If you don't know this pattern cold, your AI features will break in production.
#04
Building AI features without error handling LLMs fail silently: 429 rate limits, unexpected JSON formats, empty responses, network timeouts. A portfolio project with no error handling looks amateur. Always: try-catch on callouts, validate AI response format before parsing, log every API call, have a graceful fallback message for the user.
#05
Chasing AI trends over Salesforce depth You will see articles about fine-tuning, multimodal AI, autonomous AI agents doing everything. This is noise for your goal. Your AI depth should be: prompt engineering, REST API calls to LLMs, context injection (RAG), and Agentforce. Everything else is for after you're established in Europe.
#06
Ignoring cost in AI feature design GPT-4o costs money per token. Sending an entire case history (10,000 tokens) to OpenAI for every case creation will bankrupt a client fast. Always think: What's the minimum context needed? Can we use GPT-4o-mini instead? Can we cache results? European companies ask about AI cost governance — have answers.
#07
Tutorial Hell — applies double for AI There are hundreds of AI YouTube channels. Watching them produces zero skill. For every 1 hour of AI content consumed, spend 2 hours building an AI feature in a Salesforce org. An Apex class that calls OpenAI and parses JSON teaches you more than 10 hours of LLM videos.
#08
Claiming AI Architect without AI projects Adding "AI Architect" or "ML Engineer" to your LinkedIn without portfolio evidence is the fastest way to fail a technical screen in Europe. European hiring is evidence-based. Claim what you can demonstrate. You are an AI-enabled Salesforce Developer — and you can demonstrate 5 projects that prove it.

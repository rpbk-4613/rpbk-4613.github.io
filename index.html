02 / SKILL ROADMAP

What to Learn & In What Order

Organized by priority and dependency. Do not multitask across pillars — finish Apex before diving deep into LWC. Breadth comes after depth.

☁️ Apex (Deep Mastery)
MONTH 1–2
  • Governor Limits: Understand every limit (DML, SOQL, heap). Build instincts, not memorization.
  • Collections & SOQL: Bulkification, SOQL in loops (anti-pattern), aggregate queries, relationship queries.
  • Triggers: One trigger per object pattern, handler class pattern, avoid business logic in trigger body.
  • Async Apex: Batch (for data volumes), Queueable (for chaining), Scheduled (for time-based), Future (legacy).
  • Error Handling: DmlException, try-catch-finally, Database.SaveResult, partial save.
  • Test Classes: @testSetup, Test.startTest/stopTest, meaningful assertions, 90%+ coverage habit.
  • Security: CRUD/FLS enforcement, WITH SECURITY_ENFORCED, stripInaccessible().
⚡ LWC (Component Development)
MONTH 2–3
  • Lifecycle Hooks: connectedCallback, disconnectedCallback, renderedCallback — know when each fires.
  • Data Binding: @track (legacy), @api, reactive properties, template conditionals and loops.
  • Wire Service: @wire with adapters (getRecord, getRelatedListRecords), wire vs imperative calls.
  • Events: Custom events, bubbling/capturing, communication patterns (parent↔child, sibling).
  • Navigation: NavigationMixin, page references, navigating to records/pages.
  • Imperative Apex: Calling @AuraEnabled(cacheable=true) methods, promise chaining, async/await.
  • SLDS: Lightning Design System tokens, base components, responsive grids.
🔗 Integrations
MONTH 3
  • REST Callouts: HttpRequest/HttpResponse, JSON parsing, mock callouts in tests.
  • Named Credentials: Auth providers, per-user vs per-org — always use over hardcoded endpoints.
  • Platform Events: Event-driven architecture, publish/subscribe, replay ID, use cases.
  • Change Data Capture (CDC): Real-time change streaming, difference from Platform Events.
  • External Services: OpenAPI schema import, auto-generated Apex.
  • MuleSoft basics: Know the concepts even if not hands-on — architects are expected to assess it.
  • Middleware patterns: Point-to-point vs hub-and-spoke vs ESB vs event-driven.
🏛️ Architecture
MONTH 4–5
  • Enterprise Patterns: Selector, Domain, Service, Application layers (Apex Enterprise Patterns by Andy Fawcett — read it).
  • Sharing Model: OWD, role hierarchy, sharing rules, manual sharing, Apex managed sharing.
  • Data Architecture: Record volumes, skinny tables, indexes, external IDs, data skew.
  • Multi-org Strategy: When to split orgs, sandbox strategy, environment planning.
  • Salesforce Well-Architected: Trusted, Easy, Adaptable pillars — know this framework cold.
  • Security Architecture: SSO, OAuth flows, Connected Apps, Identity providers.
  • Deployment: SFDX, scratch orgs, unlocked packages, change sets (legacy).

THROUGHOUT

  • Git fundamentals: branching strategy (GitFlow), PRs, merge conflicts
  • GitHub Actions: Build a Salesforce SFDX deployment pipeline
  • Salesforce DX: Scratch orgs, source format, project config

06 / INTERVIEW PREPARATION

Technical Interview Playbook

European Salesforce interviews typically have 3–4 rounds: HR screening → Technical screening (Apex/LWC) → Architecture discussion → Cultural/Team fit. Prepare for all four.

Apex Interview Questions
ROUND 2
  • "How do you bulkify a trigger?" — Explain collections, avoid SOQL/DML in loops, use Maps keyed by record Id.
  • "When do you use Batch vs Queueable vs Future?" — Batch: 50M+ records. Queueable: chaining, complex types. Future: simple async, legacy. Know the limits of each.
  • "What are governor limits and how do you design around them?" — Name 5 critical ones. Explain how architecture decisions (like using aggregate queries) flow from limits.
  • "How do you handle partial save scenarios?" — Database.insert with allOrNone=false, iterate SaveResult, rollback strategies.
  • "How do you test an Apex class that makes HTTP callouts?" — HttpCalloutMock interface, Test.setMock(), StaticResourceCalloutMock.
  • "What is WITH SECURITY_ENFORCED and when do you use it?" — FLS enforcement in SOQL. Mention stripInaccessible() as the DML equivalent.
LWC Interview Questions
ROUND 2
  • "What's the LWC component lifecycle?" — constructor → connectedCallback → render → renderedCallback. Know what you can/cannot do in each.
  • "@wire vs imperative Apex call — when to use which?" — Wire: cacheable, reactive. Imperative: when you need to pass parameters, handle errors explicitly, or call non-cacheable methods.
  • "How do sibling components communicate?" — Through a common parent via custom events, or a message channel (Lightning Message Service).
  • "What is Locker Service?" — Security feature. Components cannot access DOM of other namespaces. Explain implications for third-party libraries.
  • "How do you optimize an LWC that's slow?" — Reduce reactive property updates, lazy load data, cache wire results, use pagination instead of loading all records.
  • "How do you handle errors from Apex in LWC?" — reduceErrors() utility, error.body.message, error.statusCode, toast notification pattern.
Integration Questions
ROUND 2–3
  • "Platform Events vs Change Data Capture — difference?" — PE: custom business events (you define payload). CDC: system-generated record change events. PE for custom workflows, CDC for data sync.
  • "How do you handle integration failures?" — Retry with exponential backoff, dead letter queue pattern using Platform Events, custom logging object, alerting via custom notification.
  • "REST vs SOAP — when to use each?" — REST: modern, lightweight, JSON. SOAP: legacy systems, banking/enterprise ERPs. Know WSDL, XML envelope structure at a conceptual level.
  • "How do you test a callout class?" — HttpCalloutMock, mock the response, verify the parsing logic. Emphasize you test both success and error paths.
  • "Named Credentials vs hardcoded endpoints?" — Always Named Credentials. Explain per-user auth vs per-org, OAuth 2.0 flow, why it's a security requirement not just a best practice.
Architecture Scenarios
ROUND 3
  • "Design a system for 50M records migration into Salesforce." — Batch Apex + External IDs + upsert, data skew considerations, rollback strategy, sandbox testing first, Bulk API 2.0.
  • "Client wants real-time sync between Salesforce and their ERP." — Assess: truly real-time or near-real-time? Platform Events vs CDC vs middleware (MuleSoft/AWS). Ask about volume, latency SLA.
  • "How would you design the sharing model for a financial services company?" — OWD private, role hierarchy, sharing rules, territory management. Ask about compliance requirements (GDPR in EU!).
  • "When would you recommend multiple orgs vs one org?" — Multiple: regulatory isolation (EU data residency!), separate business units, performance concerns. One: simpler, cheaper, easier reporting. Always a trade-off conversation.
  • "How do you approach a Salesforce org with 10 years of technical debt?" — Assessment → prioritization → unlocked packages for modularization → deprecation strategy. No big bang rewrites.
Mock Interview Strategy
MONTH 5–6
  • Week 19–20: Solo practice — answer questions out loud, record yourself. Watch back for filler words and clarity.
  • Week 21: Peer mock — find 1–2 people from Salesforce communities (Ohana Slack has mock interview channels) to do a full 45-min technical screen.
  • Week 22+: Real interviews are your best practice. Apply early, target less-preferred companies first to calibrate.
  • STAR format: Every behavioural answer: Situation → Task → Action → Result. European interviewers specifically look for structured thinking.
  • Prepare 3 stories: A complex technical challenge you solved. A time you disagreed with a design decision. A delivery under tight constraints. These cover 90% of behavioural questions.
  • Architecture whiteboard: Practice drawing diagrams on paper. In remote interviews, use Excalidraw or draw.io to share screen. Europeans appreciate visual thinkers.
  • Salary negotiation: Research Glassdoor + LinkedIn Salary for the specific country. UK: £65–90k for Senior Dev. Netherlands: €70–95k. Germany: €70–90k. Always negotiate — first offer is rarely best.
  • Ask good questions: "How does the team handle technical debt?" "What does the deployment process look like?" These signal seniority.

⚠️ Common Mistakes — Avoid These

#01
Tutorial Hell: Learning without building Watching 40 hours of Apex tutorials without writing code produces zero marketable skill. For every 1 hour of tutorial, spend 2 hours building something. Your fingers need to remember this, not just your brain.
#02
Cert Hoarding: Collecting certs instead of skills 3 certs with shallow depth loses to 1 cert with deep project experience. The PD2 you pass after actually building enterprise-pattern projects is a fundamentally different interview than a PD2 you cramble through.
#03
Applying too early with an empty GitHub A European recruiter who clicks your GitHub and finds 0 repos will discard your application. Apply only after Project 1 is live. Wait for Project 4 before targeting senior roles.
#04
Generic resume sent to 100 companies European ATS systems score keyword match. A resume not tailored to the job description fails ATS before a human sees it. Send 10 highly tailored applications instead of 100 generic ones.
#05
Hiding visa requirement Applying as if you're local and springing visa sponsorship mid-process wastes weeks of your time and destroys recruiter relationships. Be upfront in your cover letter and LinkedIn profile.
#06
No networking until Month 6 60–70% of tech jobs in Europe fill through referrals. Start engaging in Salesforce communities from Month 1. A warm introduction in Month 5 is worth 20 cold applications.
#07
Month 3 burnout Nearly everyone hits a wall at Month 3. The novelty has worn off but the results haven't arrived yet. This is the most common dropout point. Protect your Friday evenings. Take one full weekend off per month. This is not optional — it's structural maintenance for a 6-month sprint.
#08

10 / LIFESTYLE STRATEGY

Optimising Time, Energy & Consistency

This is a 6-month marathon, not a sprint. The person who burns bright for 8 weeks then fades will lose to the person who does 2 hours of focused work every single day for 6 months.

🧠
Protect Deep Work
Your 8:00–9:30 PM coding block is sacred. Phone on Do Not Disturb. Laptop notifications off. No WhatsApp groups during this time. Use a physical "do not disturb" signal if you live with family. This is non-negotiable — it's only 90 minutes but it compounds enormously over 6 months.
😴
Sleep is Learning Infrastructure
Sleep deprivation reduces memory consolidation by ~40%. If you sacrifice sleep for learning time, you're studying at 60% efficiency. 7 hours minimum. Study sessions after midnight are almost entirely wasted. The night before a certification exam, stop studying at 9 PM and sleep early — this is proven to improve recall.
📋
Weekly Review Ritual (Sundays, 20 min)
Every Sunday: what did I build/learn? What's behind schedule? What does this week look like? Update your Notion/Trello board. This prevents silent drift — the pattern where you feel busy but aren't making progress. Most people skip this step and regret it at Month 3.
🎯
One Thing Per Session Rule
Each coding session has one specific goal: "Implement the trigger handler for Case with bulkification" — not "work on Apex." Specificity prevents the trap of feeling productive while actually context-switching between half-finished things. Write the goal before you open VS Code.
🔄
Public Accountability
Post your Trailhead milestone on LinkedIn. Tweet when you pass a cert. Share your GitHub commit streak. This is not vanity — it creates a social commitment mechanism. The days you don't feel like coding, your public streak will pull you through. The Salesforce community also actively engages with progress posts, giving you visibility with future employers.
🏃
Physical Reset (3× per week, minimum)
30-minute walk or any exercise. Non-negotiable. Sedentary deep work for 6 months leads to cognitive decline and mood issues that undermine everything else. Exercise is not a luxury you'll add when things calm down — it's load-bearing infrastructure for the plan. Morning walks before work are ideal; they prime the brain for the day.
📵
Social Media Strategy
LinkedIn: 30 min/day MAX (use for networking, not scrolling). All other social media off during your learning hours. Install a browser extension like Freedom to block distracting sites during 7–10 PM. This single change recovers 1–2 hours per day for most people.
🧩
Manage Expectations at Home
If you live with family, have an explicit conversation: "For the next 6 months, 7–10 PM is my work time. This is how I'm changing our financial trajectory." Getting buy-in from people around you removes the invisible friction that derails plans. Family support compounds your available energy.
